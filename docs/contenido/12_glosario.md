# Diccionario: todos los términos en lenguaje llano

Cada fila explica un termino con palabras corrientes. La tercera columna dice donde aparece ese termino dentro de este proyecto concreto, no en general.

| Termino | Que significa | Como se usa en este proyecto |
|---|---|---|
| AdamW | Es el mecanismo que decide como se corrige el modelo despues de cada error, con un freno incorporado que evita ajustes exagerados. Es como un entrenador que corrige la postura poco a poco y no de golpe. | Es el optimizador del proyecto. Se construye en src/model.py y se aplica en el entrenamiento con un freno de 1e-4 sobre el tamano de los ajustes. |
| AMP (precisión mixta) | Tecnica que hace los calculos pesados con numeros mas cortos, de 16 bits en vez de 32, para ir mas rapido y gastar menos memoria sin perder calidad donde importa. | Esta activada por defecto con el campo amp. El cuaderno avisa con la linea AMP activado y se desactiva sola cuando no hay GPU. |
| Aumentación de datos | Fabricar copias alteradas de cada foto de entrenamiento, con recortes, volteos y cambios de color, para que el modelo vea mas variedad sin tener mas fotos. | Se aplica solo al entrenamiento desde build_transforms en src/data.py, con recorte aleatorio, volteo horizontal y RandAugment. |
| backbone | La parte grande y ya entrenada de la red, que se encarga de mirar la imagen. Encima se coloca una parte nueva y pequena que decide la especie. | Es EfficientNet-B0 con pesos de ImageNet, definido en src/model.py. Empieza congelado y despues se afina. |
| batch (lote) | El grupo de fotos que el modelo mira antes de corregirse. En lugar de aprender de una en una, aprende a golpecitos de varias. | El tamano por defecto es 32 imagenes de 224 por 224 pixeles. Si aparece un error de memoria se baja a 16. |
| checkpoint | Una foto fija del modelo en un momento dado: sus ajustes internos y su configuracion, guardados en un archivo para poder volver a usarlos. | Se guarda en resultados/best.pt y solo cuando mejora la exactitud de validacion. Lo usan la evaluacion y la demo. |
| clase | Cada una de las categorias posibles entre las que el modelo elige. Aqui una clase es una especie de flor. | Hay 102 clases, definidas en src/config.py. El checkpoint guarda ademas los nombres legibles de cada especie. |
| CLI | La forma de usar un programa escribiendo ordenes en una ventana de texto, en lugar de pulsar botones en una pantalla. | El proyecto incluye una CLI para entrenar, evaluar y predecir. En Colab no hace falta usarla: basta con ejecutar las celdas. |
| CNN (red convolucional) | Familia de redes pensadas para imagenes. En vez de mirar los pixeles uno a uno, peinan pequenas ventanas y detectan bordes, manchas y formas. | El modelo del proyecto es una CNN: EfficientNet-B0 mas una cabeza nueva que elige entre las 102 especies. |
| Colab | Google Colab es un cuaderno de trabajo en el navegador que se ejecuta en ordenadores de Google, con GPU gratuita. No hay que instalar nada en el propio equipo. | Es el entorno previsto para todo el flujo. El cuaderno notebooks/flores_colab.ipynb esta disenado para ejecutarse alli de principio a fin. |
| congelar y descongelar | Congelar una parte del modelo es prohibirle cambiar mientras se entrena el resto. Descongelar es volver a permitir que se ajuste. | El backbone empieza congelado durante las 3 primeras epocas y despues se descongela con una velocidad de aprendizaje mucho mas baja. |
| DataLoader | El encargado de servir las fotos al modelo: las busca, las prepara y las entrega por lotes mientras el modelo trabaja. | Se construye en src/data.py con build_dataloaders. Los de validacion y prueba no se barajan, para que la medicion sea siempre la misma. |
| dataset | El conjunto de datos: todas las fotos con su etiqueta que se usan para aprender y para medir el resultado. | Se usa Oxford Flowers-102, con 8189 fotos repartidas en 1020 de entrenamiento, 1020 de validacion y 6149 de prueba. Ocupa 330 MB y se descarga la primera vez. |
| dropout | Apagar al azar una parte de las conexiones durante el entrenamiento, para que el modelo no dependa siempre de las mismas pistas. | Se aplica en la cabeza nueva con probabilidad 0,3, configurada como dropout en src/config.py. |
| early stopping (parada temprana) | Dejar de entrenar cuando el resultado en validacion deja de mejorar, en lugar de gastar vueltas inutiles. | Esta activado con una paciencia de 6 epocas. Cuando salta, el cuaderno imprime una linea que empieza por Early stopping. |
| EfficientNet-B0 | Un modelo de vision conocido y relativamente ligero, pensado para dar buen resultado con un costo de computo moderado. | Es el backbone por defecto y la razon de que la corrida completa quepa en 15 a 25 minutos de GPU T4. |
| época | Una vuelta completa del modelo por todas las fotos de entrenamiento. Diez epocas son diez pasadas por el mismo material. | La corrida rapida usa 2 epocas y la completa 25. El limite se configura con el campo epochs. |
| época de calentamiento (warmup) | Las primeras vueltas, en las que la velocidad de aprendizaje sube poco a poco en lugar de empezar a tope, para no desestabilizar el entrenamiento. | Son 2 epocas, configuradas como warmup_epochs. En la corrida rapida se desactivan. |
| etiqueta | El nombre correcto de cada foto. Es la respuesta que el modelo debe aprender a dar. | Cada imagen de Flowers-102 trae su especie. El checkpoint guarda ademas los nombres legibles para mostrarlos en la demo. |
| exactitud (accuracy) | La proporcion de aciertos: de cada 100 fotos, cuantas clasifica bien el sistema. | Se mide en la evaluacion como top1 y top5 sobre las 6149 fotos de prueba, y en cada epoca sobre las fotos de validacion. |
| fine-tuning (ajuste fino) | La segunda fase del aprendizaje por transferencia. En vez de dejar intacta la parte ya entrenada, se retoca con mucha suavidad para adaptarla a las flores. | Empieza despues de las 3 primeras epocas, con velocidad 3e-5 para el backbone frente a 3e-4 para la cabeza nueva. |
| Flowers-102 (Oxford Flowers-102) | El catalogo de fotos de flores que usa el proyecto, creado por la Universidad de Oxford. Reune 102 especies comunes en el Reino Unido. | Es el unico conjunto de datos del proyecto. Se cargan sus particiones oficiales, con solo 10 fotos de entrenamiento por especie. |
| función | Un bloque de ordenes con nombre que hace una tarea concreta y se puede reutilizar llamandola. Es como una receta guardada. | El proyecto esta lleno de funciones con nombre claro, como train, evaluate y predict_image. El cuaderno las llama, no las reescribe. |
| función de pérdida | La nota de castigo que mide cuanto se equivoca el modelo en cada lote. Entrenar consiste en hacer que ese castigo baje. | Es la que aparece como loss en las lineas de entrenamiento. Se combina con un suavizado de etiquetas de 0,1 para que el castigo no sea excesivamente severo. |
| GPU | Un procesador especializado en hacer muchisimos calculos a la vez. Es lo que convierte el entrenamiento de una red de imagenes en cuestion de minutos. | El proyecto espera una GPU T4 gratuita de Colab. El cuaderno comprueba al principio si esta disponible y avisa claramente si no lo esta. |
| GPU T4 | El modelo concreto de tarjeta grafica gratuita que ofrece Google Colab, con 16 GB de memoria. | Es el acelerador que se elige en Entorno de ejecucion. Con ella, la corrida completa de 25 epocas tarda entre 15 y 25 minutos. |
| gradiente | La indicacion de en que direccion y con cuanta fuerza hay que retocar cada ajuste del modelo para equivocarse menos. | El entrenamiento calcula gradientes en cada lote. Durante las primeras epocas los del backbone no se usan, porque esa parte esta congelada. |
| Gradio | Una libreria que fabrica paginas web sencillas para probar un modelo: un recuadro para subir la imagen y un boton para enviar. | Con ella se construye la demo en src/app.py, con subida de imagen, camara y salida con las cinco especies mas probables. |
| hiperparámetro | Los ajustes que decide la persona antes de entrenar, como cuantas vueltas dar o a que velocidad aprender. El modelo no los aprende solo. | Estan todos reunidos en src/config.py. Cada corrida guarda los suyos en config_usada.json para poder repetirla. |
| historial | El registro de lo que paso en cada vuelta de entrenamiento: el castigo por los errores, la exactitud y la velocidad de aprendizaje. | Se guarda en history.json y sirve para dibujar las curvas y rellenar la tabla de resultados del informe. |
| ImageNet | Un catalogazo de mas de un millon de fotos repartidas en 1000 categorias, usado para entrenar de antemano modelos de vision. | El backbone del proyecto parte de pesos preentrenados en ImageNet. Si esa descarga falla, el sistema avisa y aprende desde cero con peores resultados. |
| import | La orden que trae a la memoria una pieza de codigo escrita en otro archivo, para poder usarla. | El cuaderno importa las funciones del proyecto, por ejemplo la funcion train, en su celda de imports antes de entrenar. |
| learning rate (velocidad de aprendizaje) | Cuanto se atreve el modelo a cambiar en cada correccion. Si es muy alta da tumbos, y si es muy baja tarda una eternidad. | La cabeza usa 3e-4 y el backbone 3e-5. En el entrenamiento aparece como lr y baja sola siguiendo una curva de coseno. |
| lista | Una coleccion ordenada de elementos a la que se accede por su posicion. Es como una fila numerada. | Las predicciones se devuelven como una lista de parejas especie y probabilidad, ordenada de mayor a menor. Las confusiones frecuentes tambien son una lista. |
| logits | Los numeros en bruto que produce el modelo antes de convertirlos en porcentajes. Todavia no son probabilidades, solo puntuaciones. | La cabeza del modelo produce 102 logits, uno por especie. Despues se convierten en probabilidades para mostrar las cinco mejores. |
| macro-F1 | Una nota que promedia el acierto por especie dando el mismo peso a cada una, de modo que una especie dificil no quede tapada por las faciles. | Se calcula sobre las fotos de prueba y aparece como macro_f1 en metrics.json y en el resumen que se copia al informe. |
| matriz de confusión | Una tabla cuadrada que cruza la especie real con la que dijo el modelo. La diagonal son los aciertos y todo lo demas son errores. | Es de 102 por 102 y se guarda como figura confusion_matrix.png al evaluar. Tambien se listan aparte las confusiones mas frecuentes. |
| métrica | Un numero que resume el desempeno, para poder comparar versiones y decidir si el sistema es bueno. | Las metricas principales son la exactitud top-1, la exactitud top-5 y la macro-F1, guardadas en metrics.json. |
| modelo | El cerebro entrenado: lo que queda despues de aprender y lo que responde cuando le das una foto. | El modelo final es EfficientNet-B0 con una cabeza nueva de 102 salidas, guardado como resultados/best.pt junto a la configuracion usada. |
| modo debug | El modo de prueba del cuaderno: usa un trozo pequeno de las fotos y solo 2 vueltas, para comprobar que todo funciona en minutos. | Viene activado de fabrica como MODO_DEBUG. Escribe en la carpeta resultados/debug y nunca pisa la corrida completa. |
| normalización | Reajustar los valores de los pixeles a una escala comun antes de que el modelo los mire, para que el aprendizaje sea estable. | Se aplica con las medias y desviaciones de ImageNet, definidas como constantes en src/config.py. |
| notebook (cuaderno) | Un documento que mezcla texto y celdas ejecutables, con los resultados guardados debajo de cada celda. Es el formato de trabajo de Colab. | El proyecto tiene un unico cuaderno, notebooks/flores_colab.ipynb, con 26 celdas que recorren todo el flujo de principio a fin. |
| num_workers | Cuantos ayudantes cargan las fotos del disco mientras el modelo calcula, para que nadie tenga que esperar. | Vale 2 en la corrida normal y 0 en modo debug, que es la configuracion segura para Colab en todos los casos. |
| optimizador | El mecanismo que aplica las correcciones al modelo usando los gradientes. Decide como se actualiza cada ajuste. | Es AdamW, construido en src/model.py con dos grupos de parametros: uno para la cabeza nueva y otro para el backbone. |
| overfitting (sobreajuste) | Cuando el modelo memoriza las fotos de entrenamiento en lugar de aprender la especie. Acierta mucho en lo ya visto y falla en lo nuevo. | Es el riesgo principal, porque solo hay 10 fotos de entrenamiento por especie. Se contiene con aumentacion de datos, dropout, suavizado de etiquetas y parada temprana. |
| peso preentrenado | Los valores ya guardados de un modelo que otras personas entrenaron antes, y que sirven como punto de partida. | El backbone arranca con pesos preentrenados en ImageNet. El cuaderno avisa con una nota si no se pudieron descargar. |
| píxel | El puntito de color mas pequeno de una imagen. Una foto es una rejilla de pixeles, con tres numeros por punto: rojo, verde y azul. | Las imagenes se preparan a 224 por 224 pixeles, que es el tamano que espera EfficientNet-B0. |
| precisión (y recall) | La precision mide, de todo lo que el modelo dijo de una especie, cuanto era cierto. El recall mide, de los casos reales de esa especie, cuantos encontro. | Ambas se calculan por especie en el informe detallado de la evaluacion y alimentan la macro-F1. Aparecen en el ranking de clases con peor resultado. |
| predicción | La respuesta que da el modelo ante una foto: la especie propuesta y su nivel de confianza. | La inferencia devuelve las cinco mejores predicciones con su probabilidad. Si ninguna llega al umbral de confianza, devuelve el aviso de no reconocida. |
| Python | El lenguaje de programacion en el que esta escrito el proyecto. Es de los mas legibles y se usa muchisimo en inteligencia artificial. | Todo el codigo vive en la carpeta src y en el cuaderno. Quien siga esta guia no necesita escribir ni una linea de Python. |
| PyTorch | La libreria de programacion mas usada para construir y entrenar redes neuronales. Aporta las piezas de calculo. | Es la base del proyecto: define el modelo, el entrenamiento, la precision mixta y la carga de datos. En Colab ya viene instalada con soporte de GPU. |
| RandAugment | Un metodo que aplica transformaciones aleatorias a las fotos de entrenamiento sin tener que elegir a mano cuales ni con que intensidad. | Forma parte de la aumentacion de datos del entrenamiento y esta definido en src/data.py. |
| reproducibilidad (semilla) | La capacidad de repetir una corrida y obtener lo mismo. Se consigue fijando un numero inicial, llamado semilla, que gobierna todos los sorteos. | El proyecto fija la semilla 42 al empezar. Aun asi, el resultado puede variar ligeramente entre equipos o versiones distintas. |
| requirements | La lista escrita de las librerias y versiones que necesita el proyecto para funcionar. | Esta en requirements.txt y sirve para montar el entorno en un ordenador. En Colab no se usa a proposito, porque Colab ya trae las piezas pesadas. |
| softmax | La operacion que convierte las puntuaciones en bruto en porcentajes que suman cien, faciles de leer. | Se aplica a los 102 logits para obtener las probabilidades de las cinco mejores propuestas y alimenta el umbral de confianza. |
| split (partición) | Cada uno de los trozos en que se divide el conjunto de fotos: uno para aprender, otro para vigilar el avance y otro para la prueba final. | Se usan las particiones oficiales: 1020 fotos de entrenamiento, 1020 de validacion y 6149 de prueba. No se inventan repartos propios. |
| suavizado de etiquetas (label smoothing) | En vez de exigir al modelo un cien por cien de seguridad en la respuesta correcta, se le pide algo menos, para que no se vuelva fanatico ni memorice. | Se aplica con valor 0,1. Hace que los porcentajes de la demo sean menos extremos, algo importante para que el umbral de confianza sea util. |
| tensor | Una caja de numeros ordenada por dimensiones: una lista es de una dimension, una tabla de dos y un bloque de imagenes de cuatro. | Las fotos se convierten en tensores con forma de lote, 3 canales y 224 por 224 antes de entrar al modelo. |
| top-1 y top-5 | Top-1 es acertar a la primera. Top-5 es que la respuesta correcta este entre las cinco primeras propuestas. | Son las dos metricas de exactitud que reporta el proyecto. La demo muestra directamente las cinco propuestas. |
| transfer learning (aprendizaje por transferencia) | Aprovechar lo que un modelo ya aprendio con muchisimas imagenes y reutilizarlo para una tarea nueva con pocos datos. | Es la estrategia central del proyecto: EfficientNet-B0, entrenado antes en ImageNet, se adapta a las 102 especies con solo 10 fotos por clase. |
| umbral de confianza | El nivel minimo de seguridad que se le exige a una respuesta para darla por valida. Por debajo, el sistema prefiere avisar de que no lo sabe. | Vale 0,25, configurado como min_conf. En la evaluacion responde no reconocida y en la demo muestra un aviso de confianza baja. |
| validación y prueba | Validacion son las fotos que se miran durante el entrenamiento para elegir la mejor version. Prueba son las que se guardan hasta el final para medir de verdad. | Las 1020 fotos de validacion eligen el mejor checkpoint y las 6149 de prueba producen las cifras del informe. La prueba no influye en ninguna decision del entrenamiento. |
| variable | Un nombre que guarda un valor para usarlo despues. Es como una caja con etiqueta. | En el cuaderno las variables importantes son MODO_DEBUG, que enciende la corrida rapida, y la configuracion de la corrida, que reune todos los ajustes. |
| webcam | La camara del ordenador. La demo puede usarla para hacer la foto directamente, sin pasar por un archivo. | La interfaz Gradio de src/app.py incluye una pestana de camara, ademas de la subida de archivo y el pegado desde el portapapeles. |
| ZIP | Un archivo comprimido que reune muchos archivos en uno solo y ocupa menos. Se abre con doble clic. | IA_flores_colab.zip es el paquete que se sube a Colab, con el cuaderno dentro de la carpeta notebooks. resultados_flores.zip es el paquete de resultados que se descarga al final. |
